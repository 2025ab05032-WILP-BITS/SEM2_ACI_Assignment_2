# Two-Player Sudoku Solver using Minimax Algorithm

## Overview

This project implements an intelligent two-player Sudoku game solver that determines the optimal move for either player using the **Minimax algorithm** from game theory. The program assumes both players play perfectly with complete information about the board state.

**Key Features:**
- Minimax algorithm with memoization for optimal decision-making
- Complete Sudoku constraint validation (row, column, 3×3 subgrid)
- Efficient move evaluation using dynamic programming
- Comprehensive error handling and input validation
- Well-documented code with detailed comments

---

## Problem Statement

In this two-player Sudoku game:

- **Player 1 (MAX)**: Tries to maximize their score advantage
- **Player 2 (MIN)**: Tries to minimize Player 1's score advantage
- **Scoring**: Each player earns points equal to the value they place (1-9)
- **Goal**: Find the optimal move for the current player assuming optimal play from both sides

### Constraints
- 9×9 Sudoku board
- Only valid Sudoku moves are allowed
- Both players have perfect information
- No Alpha-Beta pruning (full game tree evaluation)

---

## Algorithm: Minimax

### How It Works

The Minimax algorithm recursively evaluates all possible future game states:

1. **If it's P1's turn (MAX player)**
   - Choose the move that **maximizes** the net score (P1_score - P2_score)
   - Try all valid moves and pick the one with the highest value

2. **If it's P2's turn (MIN player)**
   - Choose the move that **minimizes** the net score
   - Try all valid moves and pick the one with the lowest value

3. **Memoization**
   - Store already evaluated board states to avoid redundant calculations
   - Dramatically improves performance for boards with multiple empty cells

### Scoring Strategy

When a player places value `v`:
- **P1's move**: Net score increases by `v` (P1 earns points)
- **P2's move**: Net score decreases by `v` (reduces P1's advantage)

The algorithm looks ahead to all possible future moves and returns the optimal outcome assuming perfect play.

## How the Code Works

### Main Functions

| Function | Purpose |
|----------|---------|
| `read_input(filename)` | Reads and validates input file |
| `get_valid_values(board, r, c)` | Returns valid Sudoku numbers for a cell |
| `minimax(board_tuple, player, memo)` | Recursively evaluates optimal moves |
| `find_best_move(board, player)` | Finds and applies the best move |
| `board_to_string(board)` | Formats board for output |
| `write_output(...)` | Saves results to file and console |

### Key Implementation Details

**Sudoku Validation:**
- Checks for duplicates in the row
- Checks for duplicates in the column
- Checks for duplicates in the 3×3 subgrid

**Memoization:**
- Board state stored as immutable tuple (lists can't be dict keys)
- Key: `(board_state, current_player)`
- Avoids re-computing the same game state multiple times

**Tie-Breaking:**
When multiple moves have equal evaluation, the algorithm chooses:
1. Move with smallest row number
2. Move with smallest column number
3. Move with smallest value

## Complexity Analysis

### Time Complexity
- **Worst Case**: O(9^n) where n = number of empty cells
- **With Memoization**: O(unique_board_states) - typically much faster
- **Per Move Validation**: O(1) - Sudoku constraint check on 27 cells

### Space Complexity
- **Memoization Dictionary**: O(unique_board_states)
- **Recursion Stack**: O(n) where n = empty cells
- **Board Representation**: O(1) - fixed 9×9 size
